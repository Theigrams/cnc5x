## 是什么

cnc5x 是五轴数控插补的教学与论文复现库。它把复现论文时反复要写的部分做成公共构件：曲线求导、弧长、拟合、S 曲线、前瞻、插补、双转台运动学、评价指标。每篇论文只写自己的那部分数学（`papers/`）。

来历：由 `五轴复现/cnc5`（GPT 写的初版，可读性差）重构而来，整体框架由 Gemini 设计。代码能跑、测试齐全，但**还没有经过用户逐行审查**；审查之前先按 [待修复问题.md](待修复问题.md) 改掉顶层设计问题。

范围（专注五轴、四类论文、只做 AC/BC、只做离线等）见 CLAUDE.md 第 1 节，复现标准见第 8 节。

## 主流程

```
刀位点 ──fitting──▶ Curve ──▶ ToolPath ──schedule──▶ Profile ──interpolate──▶ Commands ──▶ metrics
```

- **Curve**：参数曲线。子类只实现 `_derivatives(u, order)`，一次返回导数栈 `(order+1, ..., dim)`；基类提供求值、对弧长求导（`derivatives_by_length`）和自适应弧长表。五轴刀位曲线 `PoseCurve` 不是 `Curve` 的子类，而是刀尖、刀轴两条曲线的组合，求值为 6 维 `[p, o]`。
- **ToolPath**：由 block 组成，每个 block 是首尾相连的若干曲线段。`derivatives(s)` 给出全局刀尖弧长 s 处的导数栈。三类刀路：
  - G01 直接插补（`LinearPath`）；
  - G01 拐角光顺（`HermiteCornerPath` 和两篇论文，公共部分在 `PolylinePath.corner_blocks`）；
  - 整条光滑曲线（`CurvePath`，在曲率峰值处切成 block）。
- **schedule**：连接点限速 → 双向扫描（`look_ahead.bidirectional_scan`）→ 每个 block 一段七段或五段 S 曲线 → 拼成一条 `Profile`。
- **Profile**：`profile(t)` 给出 `[s, v, a, j]`。
- **interpolate**：按 `k·Ts` 采样进给轮廓，用 `calculus.compose` 把对 s 的导数换成对 t 的导数；给出机床（`kinematics.TableTilting`）时同时求机床轴及其各阶导数，全部是解析式。
- **metrics**：弓高误差、进给波动、拐角误差、连接处连续性、五轴非线性误差等。

贯穿全库的约定只有一条最重要：**导数栈 `(4, ..., dim)`**，第 k 层是第 k 阶导数；对参数、对弧长、对时间都用这个形状，链式法则只在 `calculus.compose` 一处实现。其余约定见 CLAUDE.md 第 3 节。

## 五轴进给规划的现状

平面加工的进给规划是成熟的：前瞻双向扫描加五段或七段 S 曲线，库里已经完整实现。

五轴多出来的问题是各轴约束：机床轴 q(s) 对时间的导数为

$$
\dot q = q_s v,\qquad \ddot q = q_{ss}v^2 + q_s a,\qquad \dddot q = q_{sss}v^3 + 3q_{ss}va + q_s j
$$

在极点附近，或者刀尖走得少、刀轴转得多的地方，\(q_s\) 会很大，这时刀尖进给不高，某个轴也可能超限。文献中的做法由简到繁大致有三类：

1. **按平面方法规划，再整体放慢**：库里的 `limits.time_scale_factor`。
2. **进给限制曲线**：按匀速通过时各轴不超限，算出每个 s 处的进给上限，速度规划不超过它。库里的 `limits.drive_limit` 和 `scheduler.feed_envelope` 负责算这条曲线。
3. **优化类**：直接在各轴约束下求用时最短的进给，例如 Sencer 2008、Beudaert 2012（VPOp），以及机器人领域的时间最优路径参数化。库里尚未实现。

`schedule` 里"让 block 内部也不超过包络"的逐轮加连接点做法是 Gemini 自己拼出来的，效果存疑。已决定换成保守的单遍版本，作为简单可靠的基线，见待修复问题 P1。第 3 类在范围内，将随 Sencer2008、Beudaert2012 等论文迁移进来。求解器以 SciPy 为主，其他为可选后端，见 CLAUDE.md 第 5 节。五轴进给规划的文献还没有系统调研，迁移前先调研。
